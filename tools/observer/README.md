# 小鸭硬件观测站

独立中文门户，Python 3.11+ 标准库后端、本地 JavaScript 前端，无 pip、npm 或 CDN 运行依赖。默认端口 8766。当前授权入口：`root@172.19.8.218`（原 114 设备的新地址）。

本目录是门户机制的文档入口。详细操作指南与本次实测证据位于工作区 `docs/zero3w-11servo/observer`，版本发布不修改原控制器、更新器、ONNX 或共享 IPC/TOML。

## 观测与状态

- 真实舵机：左腿 20–24，右腿 10–14，嘴 34；IMU 200。15 个逻辑槽保留，头颈 30–33 仅作固定几何参考，右腿槽位 10–14。
- 检测站独立安装，开机、安装、升级、回退均不启动；需明确运行`observerctl station start`。每次启动后采集/记录关闭，再手动开启。控制器停止、端口空闲、型号核验、扭矩为零才读取。
- 总线构包只允许身份/遥测读取与普通/Fast Sync Read；没有位置、HOME、扭矩写入接口。Fast 测试独立，结果不改变控制器配置。
- 已应答器件可用固定ID子集独立观测；缺失腿部明确离线，绝不填充实测零值。再次点开启观测会重新扫描。降级观测不计作11舵机总线验收通过。
- ToF 订阅已有 `tofd`，摄像头优先 WebRTC、快照复用 `mediad`。关闭本页视频不停止媒体服务。
- 7.4V 为用户接受条件，原始电压、协议告警、硬件错误仍展示，不作为本轮失败项。
- 暂停画面只冻结当前页面；停止采集释放串口并暂停订阅；服务开关只覆盖 tofd/mediad，影响全部客户端。
- 多个页面共享一个5Hz展示快照；独立总线默认20Hz诊断，显式选择50Hz检查原健康门槛。50Hz全链验收仍要求平均至少45Hz，不因降低诊断频率而宣布通过。UART所有权扫描300ms一次，保留500ms新鲜度门禁。
- ID14按用户要求默认OK，仅为诊断豁免；不向ID14发送查询，也不补造角度、身份或连接。其他10舵机及IMU继续检查；完整11舵机/Fast验收保持未验证。本豁免不进入运动控制器或策略。
- 普通 Sync Read 保持原控制器的 IMU200 优先线序。已核验的独占串口遇到单次 CRC/超时只丢弃该帧，最多重试两次；连续第三次失败锁止并释放串口，需手动开启重新核验。身份、所有权或扭矩变化立即释放，绝不修补坏包或自动解除锁止。
- 故障锁止持久保存。每次进程启动均不恢复旧的采集/记录意图；手动开启才清除锁止并重新核验。正常关闭保存历史状态；配置保存失败明确显示。
- 页面显示 Linux UART 接收溢出累计计数（本次开机的驱动证据），不是门户错误数；驱动未提供的字段不当作零。计数不能单独定位线缆、设备或驱动原因，需结合独立抓包与现场检查。

## 校正和声音

IMU ID200 使用已核验的型号1030/FW3、寄存器124/12契约，与 `duck-control/src/imu.rs` 黄金样本对照。默认安装旋转 +90°Y；配置只写门户持久目录。航向归零是相对参考，姿态归零不改变原始重力，10秒静止估计只扣除显示角速度偏置。运动、陈旧、样本不足拒绝保存；安装方向是明确的软件配置操作。支持撤销。

型号/FW应答和12字节解码匹配不证明MCU固件源码或实际IMU芯片身份。R15新增两秒原始姿态/角速度一致性诊断：至少8样本、跨度至少1秒、最后样本不超过1秒；姿态净变化至少3°且转速超过角速度峰值1°/s时显示“不一致”并拒绝偏置/参考归零。它不覆盖往返转动、全部动态误差或绝对精度；数据不足为未验证，原始值不被改写。通信实时状态与姿态质量分开展示，验收报告也分别记录。

“仅倾角 · 不跟随航向”是明确的显示选择，将模型航向固定为0，保留实测重力对应的横滚/俯仰；不是传感器修复，不进入10自由度控制或ONNX观测。俯仰±90°时重力不能确定横滚，显示选0。原始倾角、航向、重力始终可见。归零成功后页面自动选择校正显示坐标，原始值仍保留；偏置不回写SFLP、归零不消除后续漂移。

用设备HTTP地址访问门户；`file://static/index.html`仅作文件预览，会提示无硬件连接，不能作为检测入口。SSH登录的`robot unavailable /run/robotd.sock`来自原`/etc/update-motd.d/40-robot`；原控制器保持停止时该socket不存在，独立门户使用`/run/duck-observer/helper.sock`。不要为了消除提示启动运动控制器，门户不覆盖原登录脚本。

健康运行的原控制器可复用 `robot.sound`，它的接受回执不证明播放完成。控制器停止时，门户只播放自己持有的短音：实际配置声卡，默认10%数字幅度、上限30%、最长2秒，不改持久混音器。原音库缺失则用本目录仓库生成的私有测试音，来源明确。完成、失败、人工听音确认分别记录；停止不结束其他播放器。

## 部署、回退与审计

`deploy.py` 必须经已有 `tools/zero3w/audit_command.py` / `audited_script.py` 执行远程步骤。目录：`/opt/robot/local/duck-observer/releases/<version>`；`current`/`previous` 自有链接；数据 `/var/lib/duck-observer`。

安装保存原服务有效unit、状态、二进制、配置及模型哈希与备份，拒绝覆盖版本和非自有unit。`station.py start/stop/status`是独立入口，不依赖辅助器已运行；`observerctl station`调用同一操作层。安装/升级/回退释放资源并保持停止，明确start才核验真实HTTP及辅助器。自有unit没有WantedBy且Restart=no；启动链接只删除校验过的自有链接，不能用systemctl disable误删外部链接形式的unit定义。

部署到板端后：`python3 /opt/robot/local/duck-observer/current/observerctl station start`启动页面；`observe on --hz 20`开启低开销采集；`station stop`停止两个自有进程、采集和自有播放器。停止后没有检测站后台进程，ToF/媒体原服务保持既有状态。临时文件与持久校正/审计分开。

回退旧版本时固定使用新的工具，例如`deploy.py cli --tool-version observer-20261007-r14 ... -- release rollback --previous`，避免旧安装器恢复自动启动行为。旧版本只有文件回退，不自动恢复观测。独立目录可单独打包/停用，原程序路径和共享IPC/TOML/ONNX不改变。

服务事务恢复检测开机身份、PID、unit 指纹和状态变化，不覆盖后来的人工修改。mediad 的直接和间接依赖必须验证有效停止条件，不能借启动相机拉起控制器。所有维护动作先 fsync 审计，失败则拒绝执行。

原始数据按小时 gzip 分段，上限2GiB；达到上限只停止记录。队列/缓存有界，浏览器曲线600点，操作队列8，记录队列1000。审计、校正与备份不自动删除。ZIP导出包含完整审计、统计CSV和配置历史；原始分段单独保存。回放限定50MiB解压数据/20000记录，较长片段需分割。

本机`deploy.py export-audit`经审计SCP同步后，运行`summarize_audit.py --source <audit目录> --output <摘要.md>`，按事件ID增量追加实际IPC、程序参数、退出码及证据链接。复现CLI仅作说明，不自动执行，也不将排队/播放完成误写为验收通过。

## 验证与资产

`python3 -m unittest discover -s tools/observer/tests -v` 验证关闭接口、故障和回退边界；PTY不是实机证明。`tests/golden.rs` 引入原 Rust IMU 模块生成 `golden.json`。板端 `observerctl acceptance --duration 1800 --label <unique>` 保存每秒CSV、首次60秒、结束报告；窗口结束后采集继续。

`static/duck.bin` 是原 `robotctl/assets/duck.bin` 的逐字节副本；`math.mjs` 复用原 MIT 数学实现。`chirp-reference.wav` 用仓库 `sounds render chirp ... --seed 114` 生成。根 LICENSE 随部署包提供。版本清单记录源码提交、原基线 `a9ec4b2079ef8ee7904014089c885bb07d57d63c`、资产和全部发布文件 SHA256。

本门户不是运动控制器。IMU 已知旋转方向、绝对精度、ToF距离精度、声学输出、行走/平衡仍需现场测量，界面不能代替这些验收。
