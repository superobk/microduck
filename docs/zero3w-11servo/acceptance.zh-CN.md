## 后续逐级步骤（本轮不执行）

1. **通信与感知**：供电合规、支撑且人在场，核对11真实 ID和IMU；普通/Fast各自验收，不互相代替。确认电压/温度、位置和IMU新鲜度。任何真实腿不答复停止。
2. **支撑下 HOME**：先验证逐关节方向和限位，再由在运行daemon的 robot.init 受门禁请求。不能使用头颈固定构型的独立 CLI init。随时可以断电。
3. **零速度平衡**：60秒×5次。无跌倒、锁止、持续滑脚/顶限位；记录机器人状态JSONL、health控制循环和同步录像。
4. **低速移动**：前/后/侧移从0.03m/s、转向从0.10rad/s开始，各工况5次；先确认实际板端模型是否有足够命令响应，再提高速度。用标尺/录像测位移和朝向，不能把请求速度当实际速度。
5. **停车/切向/超时**：建立可测移动后验证停止、方向切换、500ms命令超时；没有移动不能算停车验收通过。嘴开合独立验收，不计ONNX动作。

健康门槛沿用原 update_gate：min_achieved_hz、stall_periods、max_consecutive_errors 等以板端有效配置为准。记录 loop achieved_hz、missed、last_tick_age、fault_latched和torque_off_acknowledged；订阅频率不等于控制循环频率。任何跌倒、锁止、持续滑脚、顶限位、温度/供电异常或健康门槛不满足即停止、支撑、切断动力，保留失败轨迹。单次通过不能代替5次重复。

拾取、踢球、翻滚、轮滑以及production坐起仍保持拒绝；如需开放，必须单独审查构型/命令、仿真与支撑验收，不能用训练结果替代本轮不训练目标。
